Si el terminal no es lo tuyo, lee esto

Se puede hacer la sesión completa sin escribir un solo comando. No es una versión recortada: haces la misma tarea, con los mismos prompts, y sales con lo mismo. Cambia por dónde entras.

El camino es Antigravity IDE. Se instala con doble clic como cualquier programa, es gratis y no pide tarjeta. Los otros carriles se instalan pegando comandos en una terminal, que es justo lo que quieres evitar.

  1. Descarga el IDE desde antigravity.google/download y ábrelo. Entras con tu cuenta de Google.
  2. Baja el proyecto de práctica sin usar git: descarga el ZIP, descomprímelo, y en el IDE abre la carpeta coding-agents-101/example.
  3. Pégale los tres prompts igual que todo el mundo. Son los mismos.

Si prefieres trabajar en un proyecto tuyo y ya lo tienes en la computadora, ábrelo directamente y sáltate el paso 2.

Y los comandos de git, ¿qué?

En la hora 2 hay tres momentos de git: crear el branch, ver qué archivos cambiaron, y ver el diff. No los escribes tú. Se los pides al agent.

de cada uno.
Te va a pedir permiso para correr los comandos. Dale que sí y míralo hacerlo. Eso que estás aprobando es la tool de Bash, y verla trabajar es literalmente el tema de la noche. Terminas entendiendo el loop mejor que quien lo escribió a mano.

Si abriste el proyecto de práctica desde el ZIP, ni el branch hace falta: es una copia tuya, desechable. Bórrala y bájala otra vez si algo sale mal.

Dos cosas que confunden a todo el mundo

El instalador de agy imprime líneas que dicen ERROR y no son errores. Vas a ver algo así:

ERROR: logging before google.Init: I0815 ... Appending PATH export to profile ...

Son mensajes informativos con la etiqueta mal puesta. Si al final ves ✅ Antigravity CLI installed successfully, quedó bien. Si después escribes agy y no aparece, cierra la terminal y ábrela de nuevo: el instalador cambió tu PATH.

Los "modelos gratis" de opencode no funcionan recién instalado. El instalador dice que incluye modelos gratis y opencode models lista varios con -free en el nombre, pero si intentas usarlos te dice Model ... is not supported. Primero hay que hacer /connect dentro del TUI, y eso pide cuenta y datos de facturación.

Lo mismo aplica para Pi: es bring your own key por diseño, así que sin una key de algún proveedor no arranca. El carril 4 completo asume que ya tienes con qué pagarle a un modelo. Si no, ve por el carril 2.

// vocabulario

Con siete palabras te alcanza.

Son las que cambian lo que escribes. El resto del vocabulario lo vamos agregando cuando haga falta.

agent
Un programa que corre el loop gather → act → verify con herramientas de verdad. No es un chat que escribe código: lee tus archivos y corre comandos.
context
Lo que el agent puede ver en este momento. No es lo que hay en tu repo: es lo que leyó. La distancia entre esas dos cosas explica casi todas las respuestas malas.
model
El cerebro. Se puede cambiar. Hoy el que viene por defecto está bien; no gastes la sesión escogiendo.
tools
Lo que el agent puede hacer además de escribir texto: Read, Edit, Bash, Search. Por eso te pide permiso: algunas tocan tu disco.
permission mode
Qué puede hacer sin preguntarte. Va desde preguntar todo hasta no preguntar nada. Hoy: se pregunta todo.
session
La conversación en curso, con todo lo que lleva acumulado. Cuando se enreda, no discutas con él: resetea y empieza de nuevo diciéndole qué leer.
plan mode
Un modo donde solo lee y propone, sin tocar nada. Si te da nervios soltarlo en un repo que importa, empieza aquí.
Parking lot. context window, tokens, MCP, subagents y hooks son reales y sirven, pero hoy no cambian nada de lo que vas a escribir. Context window y tokens los vemos mañana, cuando ya los hayas sentido. MCP y subagents, en la sesión 4.

Usa este.

Si tu código es de tu empresa y no quieres mandarlo a un tercero, o no quieres compartir pantalla con él, trabaja aquí. Es una decisión profesional correcta, no una excusa.

Con terminal:

git clone https://github.com/eonoe/coding-agents-101
cd coding-agents-101/example
git checkout -b agente-sesion-1

Sin terminal: descarga el ZIP, descomprímelo, y abre la carpeta coding-agents-101/example en tu IDE. No necesitas git ni branch: es una copia tuya. Si algo sale mal, la borras y la bajas otra vez.

Abre el agent dentro de example/, no en la raíz del repo. Si lo abres afuera va a leer los materiales del workshop en vez del proyecto, y el ejercicio pierde la gracia.

Es un CLI chiquito que divide los gastos de un viaje entre varias personas. Corre con node index.js, no necesita instalar nada, y tiene los problemas que tiene cualquier proyecto real al que nadie le ha dado cariño en un tiempo.

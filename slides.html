// coding agents 101 · sesión 1 de 4

Pon un coding agent
a trabajar.

Dos horas. Al final tienes un agent corriendo en tu repo y sabes por qué funcionó.

// la diferencia completa

Autocomplete predice.
Un agent corre un loop.

01 · gather

Junta contexto

Lee archivos, busca, corre comandos para entender dónde está parado.

02 · act

Actúa

Escribe, edita, ejecuta. Aquí te pide permiso.

03 · verify

Verifica

Corre lo que escribió y revisa si sirvió. El paso que todos se saltan.

// cuando algo sale mal

El diagnóstico
siempre empieza igual.

  1. ¿Falló el gather? No leyó lo que necesitaba.
  2. ¿Falló el act? Leyó bien pero hizo mal.
  3. ¿Falló el verify? Hizo mal y no se dio cuenta.

Casi siempre es el gather. Eso es la sesión de mañana.

// para cualquier herramienta nueva

Cinco preguntas
y ya estás ubicado.

  1. ¿Dónde escribo?
  2. ¿Dónde veo lo que está haciendo?
  3. ¿Dónde me pide permiso?
  4. ¿Dónde veo el diff?
  5. ¿Cómo lo reseteo?

// hora 2

Tres prompts,
no uno.

p1 · gather

Que lea

Explora y no toca nada. Termina con: dime qué archivos leíste.

p2 · act

Que escriba

ONBOARDING.md. Lo que no pueda verificar va bajo ## Sin confirmar.

p3 · verify

Que se revise

Como reviewer hostil, citando archivo y línea.

Un prompt grande te devuelve una caja negra. Tres te dejan ver el loop.

// lo que reportas

Una cosa que
el agent hizo mal.

Una sola. Todo el mundo encuentra una — y eso es exactamente lo que queremos ver.

[nombre] | tarea A o B | ✅ / ⚠️ / ❌ | UNA cosa que hizo mal

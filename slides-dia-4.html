// primero · skills

Una skill es un workflow
que dejaste escrito.

No es un plugin ni código. Es texto con tres partes.

1 · Cómo se llama

Una línea. "Revisar un PR de este repo".

2 · Cuándo se usa

Una frase. Es lo que hace que la cargue solo, sin que la pegues.

3 · Los pasos

En orden, y qué verificar en cada uno.

// no compiten

AGENTS.md entra siempre.
La skill, cuando toca.

  1. El AGENTS.md se manda completo en cada sesión. Por eso cada línea te cuesta context, y por eso es corto.
  2. La skill solo entra cuando la tarea encaja. Por eso puede tener los pasos completos sin estorbar.

Una regla va al AGENTS.md. Unos pasos son una skill.

// cuándo algo merece ser skill

La regla de
las dos veces.

  1. Lo hiciste dos veces. Los mismos pasos, en el mismo orden.
  2. Lo explicaste dos veces. El mismo prompt largo, en dos sesiones.
  3. Te corrigió lo mismo dos veces. Cuidado: eso suele ser una línea del AGENTS.md, no una skill.

El homework de anoche era justo esto. Lo que trajiste es el material de la hora 2.

// segundo · MCP

MCP es cómo alcanza
lo que está afuera.

Sus tools eran las de fábrica - leer, editar, correr comandos - y todas dentro de tu repo. MCP le conecta otras sin que nadie programe una integración por cada agent.

01 · el server

Quién ofrece

Un programa que dice "yo sé hacer estas cosas". Local o en la nube.

02 · las tools

Qué puede hacer

Una lista con nombre y parámetros. El agent escoge, como con las de siempre.

03 · el permiso

Quién aprueba

Tú. Y con tools que mandan correos, eso deja de ser un detalle.

// lo que nadie te dice al conectarlos

Cada MCP conectado
te cuesta context.

La lista de tools viaja en cada llamada: nombre, descripción y parámetros de cada una. Lo mismo del martes, por cada server que conectes.

  1. Veinte servers = menos sitio para tu código.
  2. Y escoge peor: cien tools donde le bastaban seis.
  3. Conecta lo que vas a usar hoy. No todo lo que existe.

// esto no se negocia

Dos reglas antes de
conectarle tu correo.

  1. Lo que lee, entra al context. No conectes la cuenta que tiene cosas que no le enseñarías a una herramienta.
  2. Nada se manda sin que tú lo leas. Un agent que escribe correos y ejecuta sin permiso es la peor combinación de la semana.

// dónde no

Dónde un agent es la
herramienta equivocada.

  1. No puedes verificar el resultado. Da igual lo rápido que salga.
  2. El error no tiene vuelta atrás. Migraciones, producción sin revisión, lo que se manda a un cliente.
  3. El problema es decidir, no ejecutar. Te da una respuesta segura a algo que nadie ha decidido.
  4. El trabajo es aprender. Que lo escriba él es lo contrario de lo que necesitas.
// la semana que viene

Tres cosas chiquitas.

  1. Una línea más al AGENTS.md cada vez que algo te dé rabia.
  2. Una skill más la segunda vez que escribas el mismo prompt largo.
  3. Un MCP, el que uses de verdad. Uno. Después piensas en el segundo.
